# ModPort 桌面版

桌面版使用当前工作区的完整工作流，目前为 v43，应用版本为 1.0.1。工作流定义迁移方法；迁移实例是一次实际
执行；源码目录保存框架程序。这三个对象分别管理。

Linux 解压后运行 `ModPort`，Windows 解压后运行 `ModPort.exe`。启动的是
独立桌面窗口，默认最大化。包内提供 Electron、Python 和指定版本的
OpenCode，不需要先安装 Python、Node.js 或 OpenCode。程序文件和迁移
数据分开保存；请把包解压到本地目录，
不要从压缩包里直接运行。

界面支持简体中文和英文。首次启动读取操作系统的语言偏好，优先使用其中支持的中文或英文，
均不支持时回退英文。右上角语言图标旁可随时切换，项目、预算、
模型和对话草稿保持不变；选择保存在应用数据目录的 `ui-settings.json`，
重开窗口继续使用。语言仅影响界面、原生提示及服务自身的展示文案；
项目名称、路径、模型回复和原始诊断保留原文，不改变实例的冻结输入。

命令行也支持中英文，例如 `modport --lang zh-CN --help` 和
`modport run --lang en --help`。手动选择记在 ModPort 用户数据目录的
`cli-language.json`，与桌面偏好分别保存；未选择时跟随系统语言。
参数名、状态码和 JSON 输出字段保持稳定，便于脚本调用。

项目页填写项目名称、GitHub/Gitee 仓库以及分支或标签。读取版本信息只
读取仓库文件，不执行仓库代码；自动识别结果可以修改。设置页填写整体
时间和 Token 预算。执行页默认显示 Supervisor 对话；上方“执行总览”可展开
查看用量、工作区以及准备、实施、测试三组中的实际子任务。总览和聊天
分别使用完整内容区，点击“Supervisor 对话”或收起总览即可返回聊天。
消息在上方滚动，输入框保留在下方；切换视图、刷新或切换语言保留草稿，
查看较早消息时不会因普通刷新自动跳回底部。

闭源或尚未发布的项目可切换到“本地代码库”，通过系统文件夹选择器
选择源码目录。程序检测 Git 状态，并提供三种开发目录模式：

- **新建 Git 分支工作区**：对于已有提交且干净的仓库根目录，默认采用此模式。
  填写一个尚不存在的分支名，在原目录旁创建独立 Git worktree，保留源码历史；
  迁移提交进入新分支，原目录当前分支和文件保持不变。有未提交修改时先提交，
  或选择复制目录、直接开发。
- **复制为独立工作区**：默认用于没有 Git 的目录，也可主动选择。复制当前源码
  （包括未提交修改）到原目录旁的新目录，在副本中开发，原目录不被修改。
- **直接在原目录开发**：明确勾选确认后，直接修改所选目录，不创建工作分支或
  备份目录。保留原有 `.git`、分支和索引；框架自己的提交记录放在实例数据中。
  失败时保留已经写入的修改，不自动硬重置原目录。

实例保存源码输入快照和选定开发目录；恢复沿用该目录，不重新复制、不再创建
分支。同一个应用数据目录中的并发实例不能占用相互重叠的开发目录。执行页
显示实际路径、模式和分支，可点击“打开工作目录”查看源代码和构建结果。
本地模式不需要远程仓库地址。源码仍会发送给
所配置的模型 API；离线使用需要另行配置本机模型服务。

采集排除 `.git`、构建/缓存目录（如 `.gradle`、`build`、`run`、`runs`、
`logs`、`node_modules`、`.venv`）以及 `.env`、`.ssh`、`.aws` 等明确命名
的凭据目录或文件；`.env.example` 等示例文件保留。排除目录按一个
入口计数，不读取其内容。这不是对任意源码中嵌入密钥的检测。
符号链接、Windows 目录联接及非常规文件不跟随，遇到时提示处理。
快照限制为 20,000 个文件、单文件 64 MiB、合计 1 GiB，创建上限
60 秒；超出时保留原目录并提示失败。源目录不能与应用数据目录重叠。

顶部的项目、设置、执行页可随时切换，项目未完成也可查看后续界面。
未创建实例时执行页显示空状态；只有点击“开始迁移”才检查项目与工作区必填项。
本地文件夹选定后，在项目页直接选择 Git 分支工作树、复制源码或直接修改原目录。

首页右上角的“配置模型”无需先填写项目。界面依次引导填写 API 地址与密钥、
困难任务模型、常规 Coder 模型。困难任务模型用于规划与需求审查；常规模型
用于代码编写、监督、摘要及其他默认任务。常规模型默认共用第一个 API，
也可使用独立 API 连接，或点击按钮共用困难任务的模型与推理强度。
两个用途均需确定；允许明确选择同一模型。各模型的上下文窗口、最大输出
Token 和推理强度应按服务实际规格填写。协议支持 OpenAI Responses 和
兼容 Chat Completions。高级配置保留多个连接、分组与逐角色编辑；已有显式
阶段覆盖、子任务覆盖及 fallback 默认保留，界面提示覆盖数量。

展开“备用模型（可选）”可统一配置所有角色与阶段的备用模型，使用已有
API 连接，或新增独立 API、模型与推理强度。也可保持各项已有设置，或
关闭所有备用模型。与主模型及推理强度完全相同的项无需另设备用。
明确的认证、额度、限流、模型不可用及服务不可用错误，沿用运行时机制
最多切换一次；普通超时、取消和已执行工具的失败回合不会自动重放。
保存不发起模型请求，新的实例冻结备用配置与相应连接凭据。
整体 Token 预算仍在迁移设置页单独填写，不等同于模型上下文窗口。

“子任务”默认跟随代码编写模型与推理强度；可展开角色设置单独选择，
点击“沿用代码编写模型”恢复继承。子 agent 使用父任务的期限、用量额度和
沙箱；`explore` 只读，`general` 的修改权限受父任务限制。

配置保存在应用数据目录的私有 `model-settings/settings.json` 中；
密钥使用本机文件权限保护，不会回传到界面，也不写入 Run 参数。
这不是系统凭据库加密。密钥留空保留已存密钥；移除连接会移除该
连接的已存密钥。取消窗口放弃本次编辑。保存不发起模型请求。
新实例启动时复制连接与密钥到私有启动快照，恢复使用同一快照；
之后修改通用设置不改变正在执行的实例。

源与目标加载器均可填写 Forge、NeoForge 或 Fabric，加载器版本随实例
保存。Fabric 源项目可从 Gradle 中的 Fabric 声明识别 Loader 版本；
Fabric API 版本不会当作 Loader 版本。当前 Fabric 改动仅覆盖表单、
识别和提交字段；环境锁定仍使用 NeoForge 元数据与 MDK，尚未支持
Fabric 目标环境准备，也未完成 Fabric 迁移验收。

每个子任务分别显示 Agent/Subagent 数量。未知数量显示“未知”；未开始
任务暂不展示；已完成和空间不足的条目可以展开。Supervisor 对话读取
实例证据，消耗同一预算；取消实例使用明确的取消按钮。

SDK 的任务调度状态与工作进程存活状态分别展示。任务仍为 running 时，
已观察到的工作进程也可能已退出。进程身份缺失、过期、命名空间无法核实或
进程不可访问时显示“未知”，不由心跳或调度状态推定存活。状态读取使用
SDK 公共观测存储绑定；短时观察查询不保证整个状态请求在亚秒内返回。
进程存活、退出或 SDK 结算都不代表迁移通过目标行为验收。

合并 coder 补丁时保留当前候选与用户修改。真实 Git 冲突进入已授权的集成
修复任务：新 coder 在隔离副本中保留各任务修改意图、解决冲突并返回补丁，
随后重新执行原集成阶段。集成未完成或修复未返回实际补丁时不会继续清理、
合同冻结或构建。修复使用原截止时间和剩余预算，重启驱动不重复派发同一任务。

关闭窗口不会取消已提交实例。Linux 使用 systemd，Windows 使用任务
计划程序分别监督驱动和独立 watchdog；意外退出恢复同一实例，保留冻结输入、原截止
时间和累计预算。重新打开桌面版从实例列表进入原实例。

Linux 驱动成功退出为 `0`；SDK 失败、取消或等待恢复退出为 `78`，systemd
禁止直接重启该退出码。启用 watchdog 的 Run 由独立进程读取 SDK 状态，
在原预算内先唤起主管诊断失败；主管明确修复后才恢复任务。清理尚未确认
时继续保留等待与原因。watchdog 不恢复成功或用户取消的实例。宿主异常或没有终态、恢复等待的意外返回才触发驱动自身恢复；
15 分钟内最多启动三次。已结束的 SDK 执行在再次启动时只读确认状态，
不会重放业务任务。失败原因及语义退出码保存于 `desktop-driver-state.json`。
Windows 调度器无法按退出码排除重启，因此入口将已处理的 `78` 转为进程
退出 `0`；业务失败及原因仍保存在 SDK、状态投影和驱动记录中，不能据此
把任务计划程序的进程成功解释为迁移成功。此边界仍需原生 Windows 验证。

watchdog 的活动与最近恢复诊断记录在 `desktop-watchdog-state.json`，
取消控制记录在 `desktop-watchdog-control.json`。模型或工具会话十分钟
没有真实响应会请求主管诊断；持续输出但三个观察窗口没有实质进展也会
触发诊断。心跳和进程存活不等于工作正在推进。关闭桌面不会停止这两个服务。

可选 watchdog 观测遇到 SQLite BUSY/LOCKED 时记录原始错误，按有界冷却
重试，避免观测写锁竞争导致迁移驱动退出。SDK 初始化时观测存储不可用则
明确等待下一次公开 Runtime 重新打开，不显示本次监测已经恢复；其他数据库、
身份及认证错误仍保留原错误路径。

驱动启动或显式恢复只处理精确匹配的当前执行。旧驱动必须在可核实的 PID
命名空间中确认已退出，SDK 持久证据也必须证明对应工作进程树已清理；仅
工作进程或主管退出不构成整树清理证明。未完成的 Effect 进入主管诊断，
不盲目重放作者。主管明确请求修复后，宿主保留取消授权和独立停止证明，
应用收尾记录为失败且部分产物未验收，SDK 清理 unknown 保持原样。若中断
的是活动 watchdog 主管，只做失败诊断收尾，由已有的 60 秒诊断重试策略
派发新主管；不捏造主管决定，也不直接重跑业务作者。缺失或不确定证据继续
显示等待原因。用户取消不会触发恢复，原截止时间和累计预算始终保留。

支持的工作流继续操作可以在同一目录建立 SDK 后继执行。桌面实例 ID、
监督器及私有启动环境保持原有绑定，`execution_run_id` 标识当前 SDK 执行；
状态、消息和开发目录仍归属原桌面实例，冻结截止时间和累计预算不因驱动
重启而变化。

当前只支持宿主明确选定并携带的一个旧实例按其冻结来源工作流版本续接；
不能仅按版本号推定资格，公开发行包不携带私有实例选择，其他旧实例不获得
兼容承诺。升级保留已执行历史，已有禁用或持久停止的 watchdog 不会重新开启。

运行迁移仍需 Git、合适版本的原生 JDK及可用的
模型凭据，可通过“配置模型”填写。界面中的环境检查给出缺项。模型配置与工作流版本分别保存，
修改模型不改变工作流版本。程序不会自行安装系统软件或修改账号凭据。

Linux 执行项目代码使用 bubblewrap；Windows 使用原生 AppContainer
文件权限隔离和 Job 进程树约束。沙箱不可用时执行失败，不降级为直接
执行宿主机项目代码。Windows 不需要 WSL。

对于上述本地开发目录，项目命令使用过滤后的临时构建目录执行，再同步文件
变化。运行期间请勿同时编辑开发目录。同步前检查原文件是否被修改；检测到
冲突则保留原文件并报告失败。Linux 文件锁是协作式锁，无法保证捕获忽略锁的
编辑器恰好在检查与写入之间发生的修改。
凭据和原仓库的 Git 元数据不会挂载给项目命令。隔离构建使用当前源码的独立
Git 快照，其提交 ID 与原仓库不同，依赖原始完整 Git 历史的构建脚本需相应调整。

Token 数量来自供应方实际回报。未回报、缺失统计或正在请求时显示相应
未知状态；恢复不清零。达到上限后阻止后续请求并取消在途执行。供应方
在响应结束后回报用量，因此流式响应可能超额；程序不宣称具有供应方
不支持的逐 Token 硬限制。

Windows 包目前提供测试版本。原生 Windows 启动、任务计划程序恢复、
AppContainer 权限拒绝、文件锁及真实目标 GameTest/客户端验收，需要
真实 Windows 10/11 环境验证。Linux 的实际验证结果另见交付记录。
异常退出后未确认的 AppContainer 权限或配置文件清理会保留诊断；当前
未实现遗留配置文件的自动回收，不应把驱动恢复视为权限清理已完成。

从源码启动：安装当前 ModPort 和 SDK 后，用官方 Electron 运行
`desktop/`。构建包使用 `scripts/build_desktop.py`，只包含当前源码及
运行时，不包含历史迁移实例、SDK 数据库、模型凭据或源代码归档。

## 应用更新

桌面窗口启动后在后台检查 `FlightDan/ModPort` 的 GitHub Releases 正式版，
发现新版时底栏显示版本提醒。设置页和底栏均可打开“应用更新”，查看当前
应用版本、检查结果和上次检查时间，手动重试或前往发布页选择对应平台下载。
检查使用桌面 `package.json` 的应用版本，不使用工作流版本。
网络失败、限流或没有正式版不会阻止启动及迁移；检查不会发送模型密钥、
项目源码或实例数据，也不会自动下载、安装或重启应用。
